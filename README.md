# PCCS in Go (unofficial)

**!! DO NOT USE IN PRODUCTION !!**

An independent personal Go port of
[Intel's PCCS](https://github.com/intel/confidential-computing.tee.dcap.pccs),
maintained by toratako, with no Intel affiliation, endorsement, or support.
Report port-specific vulnerabilities through [SECURITY.md](SECURITY.md).

A single server/admin executable provides local TLS setup and a persistent
cache using only the Go standard library: no Node.js, database server, or CGO.

Requires **Linux** for file locking and **Go 1.23+** to build. Configuration and
storage are separate from Node.js PCCS;

## Quick start

```sh
go build -o bin/pccs ./cmd/pccs

# Initialize and start
./bin/pccs init
./bin/pccs config check
./bin/pccs serve
```

`init` refuses existing directories and creates private `pccs/` configuration, `ca.crt`, localhost TLS credentials, and `admin.token` / `user.token`.  
`serve` listens on **<https://127.0.0.1:8081>**.

In another terminal:

```sh
./bin/pccs health
./bin/pccs platforms list
curl --cacert pccs/ca.crt https://127.0.0.1:8081/healthz/ready
```

Admin commands find tokens and the CA beside the config. PCK retrieval needs
an Intel PCS subscription key in `PCCS_API_KEY` or config `api_key`; health
checks and offline registration do not.

For a different instance directory:

```sh
./bin/pccs init --dir ./my-pccs
./bin/pccs serve --config ./my-pccs/config.json
./bin/pccs health --config ./my-pccs/config.json
```

## Common operations

```sh
# Register PCK ID retrieval output.
./bin/pccs platforms register --file platform.json

# Read cached platforms without draining queues.
./bin/pccs platforms list --source '[]'

# Export and drain pending offline registrations.
./bin/pccs platforms list --source reg > platform_list.json

# Import an Intel PCS Client Tool v4 bundle.
./bin/pccs collateral import --file platform_collaterals.json

# Refresh collateral, all PCK certificates, or one FMSPC.
./bin/pccs refresh
./bin/pccs refresh --fmspc all
./bin/pccs refresh --fmspc 00906ED50000

# Securely store a new token and update its *_token_hash in server config.
./bin/pccs token generate
./bin/pccs token hash < pccs/user.token
```

Registration accepts one JSON object with `qe_id` and `pce_id`, plus either
`platform_manifest` or all of `cpu_svn`, `pce_svn`, and `enc_ppid`.

`--source reg_na` drains unavailable-TCB registrations; `--source
'[FMSPC1,FMSPC2]'` filters cached platforms.

Remote clients use `--url https://host:8081` (origin only) and `--ca /path/to/ca.pem`.

## Configuration

Precedence: flags > environment > JSON > defaults. `PCCS_CONFIG` selects the config file (default `pccs/config.json`).  
JSON paths are relative to that file; environment/flag paths are relative to the working directory.

| JSON setting              | Environment                      | Default / purpose                                  |
| ------------------------- | -------------------------------- | -------------------------------------------------- |
| `listen`                  | `PCCS_LISTEN`                    | `127.0.0.1:8081`                                   |
| `data_dir`                | `PCCS_DATA_DIR`                  | `data`, relative to config                         |
| `mode`                    | `PCCS_MODE`                      | `LAZY`; also `REQ`, `OFFLINE`                      |
| `pcs_url`                 | `PCCS_PCS_URL`                   | Intel SGX PCS v4 base URL; TDX is derived          |
| `api_key`                 | `PCCS_API_KEY`                   | Intel PCS subscription key                         |
| `proxy`                   | `PCCS_PROXY`                     | Empty uses `HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY` |
| `tls_cert` / `tls_key`    | `PCCS_TLS_CERT` / `PCCS_TLS_KEY` | Generated by `init`                                |
| `user_token_hash`         | `PCCS_USER_TOKEN_HASH`           | SHA-512 hash; empty denies registration            |
| `admin_token_hash`        | `PCCS_ADMIN_TOKEN_HASH`          | SHA-512 hash; empty denies administration          |
| `collateral_root_ca`      | `PCCS_COLLATERAL_ROOT_CA`        | Optional PEM trust roots for collateral signatures |
| `upstream_timeout`        | `PCCS_UPSTREAM_TIMEOUT`          | `120s` per PCS request                             |
| `refresh_interval`        | `PCCS_REFRESH_INTERVAL`          | `24h`; `0s` disables scheduled refresh             |
| `shutdown_timeout`        | `PCCS_SHUTDOWN_TIMEOUT`          | `30s` for graceful HTTP shutdown                   |
| `max_body_bytes`          | `PCCS_MAX_BODY_BYTES`            | `2097152` (2 MiB)                                  |
| `max_cache_bytes`         | `PCCS_MAX_CACHE_BYTES`           | `134217728` (128 MiB); encoded snapshot limit      |
| `max_concurrent_requests` | `PCCS_MAX_CONCURRENT_REQUESTS`   | `128`; maximum concurrent backend requests         |
| `log_level`               | `PCCS_LOG_LEVEL`                 | `info`; `debug`, `warn`, `error` also supported    |

`serve` supports `--listen`, `--mode`, and `--data-dir`. Refresh intervals run
from process startup, replacing cron; they refresh collateral, not PCK
certificates, which require explicit refresh.

| Cache mode | Public read misses                         | Registration                                           | Refresh                              |
| ---------- | ------------------------------------------ | ------------------------------------------------------ | ------------------------------------ |
| `LAZY`     | Retrieve from PCS and persist              | Retrieve missing platform collateral                   | Online                               |
| `REQ`      | Return cache-miss status without PCS calls | Queue, retrieve collateral, then complete registration | Online                               |
| `OFFLINE`  | Return cache-miss status without PCS calls | Queue for offline export/import                        | Disabled; manual request returns 503 |

Use one process per dedicated local data directory. Updates rewrite the JSON
snapshot atomically with fsync; this suits modest deployments, not shared
storage. Cache hits remain available during refresh. Failed imports/staged
refreshes preserve committed data; registration may retain partial progress
and its pending request after PCS failure.

`max_cache_bytes` bounds encoded disk size, not memory. Oversized updates return
503 without eviction or partial writes; oversized snapshots prevent startup
without modification. Excess concurrent work returns 503 while liveness stays
available. Request deadlines are `max(5m, upstream_timeout + 15s)`; HTTP headers
are limited to 16 KiB.

## API compatibility

The v4 API preserves PCCS authentication, status codes, and collateral headers:

| Prefix                   | Endpoints                                                                                                                                      |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `/sgx/certification/v4/` | `pckcert`, `pckcrl`, `tcb`, `qe/identity`, `qve/identity`, `rootcacrl`, `crl`, `platforms`, `platformcollateral`, `refresh`, `appraisalpolicy` |
| `/tdx/certification/v4/` | `tcb`, `qe/identity`                                                                                                                           |
| `/healthz/`              | `live`, `ready`, `startup`                                                                                                                     |

PCK selection uses Intel's type-0 algorithm with little-endian PCE SVN and
partially ordered TCB components. Multi-package manifests and `standard` /
`early` collateral are supported. Status codes: missing platform 461, missing
collateral 404, integrity failure 460, upstream failure 502.

Legacy encoding is intentional: `pckcrl` defaults to hex DER with
`application/x-pem-file`; `encoding=der` returns binary DER. `rootcacrl` returns
hex DER, `crl` binary DER, and issuer-chain headers remain URI-encoded. The
Python PCCS Admin Tool can target these endpoints using `--ca`.

Differences from the Node.js service:

- v3 routes return 410. Only v4 collateral bundles are imported.
- HEAD is rejected for `platforms` and `refresh`, whose GET operations may
  change state. Other read endpoints support HEAD.
- Request JSON is strict about duplicate fields and requires
  `Content-Type: application/json`. Registration and appraisal-policy objects
  reject unknown fields.
- New/imported collateral is checked for chains, signatures, consistency, and
  validity. Cached entries remain until refresh/import, including offline;
  consumers must still verify attestation and freshness.
- There is no system-service installer, Windows runtime support, or native
  FIPS-mode switch.

There is no SQL migration: use a separate instance and repopulate via
registration/PCS or a v4 collateral import, preserving the original database.

## TLS and trust

Generated certificates cover `localhost`, `127.0.0.1`, and `::1` for one year.
Remote access needs a matching server certificate/key, a changed `listen`, and
client trust. TLS may terminate at a local reverse proxy; `serve --http` permits
plaintext only on loopback. PCS HTTPS verification remains enabled, redirects
are rejected, and CRL destinations are allowlisted.

By default, fetched collateral trusts authenticated PCS; imports trust the
administrator-supplied root. Valid signatures/chains alone do not establish
Intel trust. Pin an independently trusted root bundle with `collateral_root_ca`;
this is separate from the HTTPS server's `ca.crt`. Quote verification remains
the consumer's responsibility.

With pinning, startup validates saved chains, signatures, validity, and supplied
CRLs. Untrusted/expired snapshots prevent startup: restore fresh trusted
collateral or use a separate data directory. Direct CRL retrieval then requires
a cached issuer chain; populate PCK CRL or identity collateral first. HTTPS
alone does not authenticate a CRL under pinned roots.

Capacity limits provide neither per-client rate limiting nor a PCS
spending quota; enforce rates and access policy at ingress.

Back up the private instance directory while stopped, including `data/state.json`
and `data/.lock`. Missing/corrupt state fails rather than silently resetting.
